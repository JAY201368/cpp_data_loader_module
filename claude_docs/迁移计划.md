**斗兽棋（斗兽棋）迁移计划**

## 执行摘要

本文档概述了将国际象棋 NNUE 训练数据加载器迁移到斗兽棋（斗兽棋/Animal Chess）的**持续集成方法**。该策略侧重于增量更改，并在每个步骤进行验证，以防止级联错误。

## 关键差异：国际象棋 vs 斗兽棋

### 棋盘结构
- **国际象棋**: 8×8 (64 格)
- **斗兽棋**: 7×9 (63 格)
    - 包含：2 个兽穴，6 个陷阱，2 条河流（每条河流 3×2 格）

### 棋子
- **国际象棋**: 6 种棋子类型 × 2 种颜色 = 12 种棋子-颜色组合（在某些特征集中排除王：10 种）
- **斗兽棋**: 8 种棋子类型 × 2 种颜色 = 16 种棋子-颜色组合
    - 象、狮、虎、豹、狼、狗、猫、鼠

### 关键差异
1.  **无王**：斗兽棋有兽穴，没有王。
2.  **特殊地形**：陷阱、河流和兽穴影响移动和吃子规则。
3.  **棋子强弱等级**：鼠可以吃象；在陷阱中的动物可以被任何棋子吃掉。
4.  **移动类型**：无王车易位、吃过路兵或升变。

## 风险管理

### 高风险区域

1.  **位棋盘假设**：
    - 风险：63 个格子不能干净地放入 64 位位棋盘
    - 缓解措施：使用 64 位，其中一位未使用，或改用不同的表示法

2.  **移动生成复杂性**：
    - 风险：斗兽棋规则（河流跳跃、陷阱）复杂
    - 缓解措施：从简化规则开始，逐步增加边界情况

3.  **特征集兼容性**：
    - 风险：现有训练代码假设国际象棋特征维度
    - 缓解措施：尽早与 Python 端协调（阶段 5.3）

4.  **二进制格式更改**：
    - 风险：现有的 .binpack 工具可能损坏
    - 缓解措施：将国际象棋读取器保留在单独的分支中，或对格式进行版本控制

### 回滚策略

每个阶段都有一个 git 提交。如果某个阶段失败：
1.  使用 `git bisect` 识别失败的提交
2.  回退到最后一个正常工作的提交
3.  创建最小化复现器
4.  使用更小的提交进行增量修复
